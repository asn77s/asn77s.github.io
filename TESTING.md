## Scope and current status

Live site: https://asn77s.github.io/

Website revisions under test: **49d639e** for the initial run and **4f0b2d3** for interactive downloads and updated instructions. The project page was rechecked after deployment.
Environment: macOS; Codex in-app browser for live UI tests (browser version not exposed), 390 × 844 phone viewport and 1280–1366 px laptop viewports. Lighthouse used official CLI version 13.6.0 and Headless Chrome 156.0.0.0 against live HTTPS pages, with mobile and desktop presets. UTC timestamps in JSON correspond to November 4 in America/New_York. Screenshots and browser-observed records are saved under `tests/evidence/`.

All 57 recorded cases have passed, including two completed with Adrian’s device confirmations. **Not run** means no result has been verified and must be replaced with Pass or Fail after executing the test. Earlier localhost and Python unit checks are not counted as live-site passes here. No unresolved live-site product failure was reported in these checks. Results describe the recorded runs, not a guarantee of all future behavior.

## How to finish the tests

1. Use the live website, not a local preview. Confirm the latest deployment has loaded.
2. Record the date, browser/version, operating system, and viewport for each run.
3. In desktop Chrome, use device mode to test at 390 × 844 and 1366 × 768. Also try a real phone when available.
4. Execute each pending row. Replace its result with **Pass — actual observation** or **Fail — actual observation**. Do not mark a whole case Pass if only part was checked.
5. For Lighthouse, open each live page in Chrome, open DevTools > Lighthouse, select Accessibility, and run separately for Mobile and Desktop. Save reports and enter both scores. Aim for at least 90 on every page.
6. On failure, retain the original result in the history table below. Describe the fix and commit, rerun against the deployed fix, and record the new result. Do not erase failed runs.

There is no contact form; email-link tests apply instead. Input validation tests cover the gradebook and calculator. JavaScript coverage includes the mobile menu, resize handling, Escape behavior, theme toggle, all demos, random pricing, reset, and joke downloads/errors.
